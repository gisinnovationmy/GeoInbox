Host connectors

The host is the authoritative copy of your data — usually a GeoPackage file or PostGIS database. GeoInbox reads it for comparison and writes back when you commit approved changes.

Supported hosts

TypeReadWrite / commitNotes
GeoPackageYesYesSingle file; good for desktop workflows
PostGISYesYesPostgreSQL connection; schema-aware
ShapefileYesNoCompare only; cannot commit back to shapefile host

Transactional commits

When you commit from the Versioning tab, GeoInbox applies inserts, updates, and deletes inside a database transaction where the backend supports it. If something fails mid-commit, the host should roll back to a consistent state.

Automatic backup

Before modifying a host layer, GeoInbox can export affected data to timestamped GeoJSON files under your download folder (backups/). Use these for manual recovery if needed. Enable or confirm this behaviour in Settings (Backup before commit).

Undo and redo

Recent commit operations can be undone or redone from the versioning UI when the connector supports operation history for that host. See Data versioning.
